# Reel knowledge extractor behavioral evaluation

All project names and domains in these fixtures are synthetic. Evaluations used supplied evidence only: no browsing, downloads, paid calls, installation of promoted tools or contact with creators.

## Fixtures and expected behavior

1. Sampled frames show a polished 3D wine website. Export caption offers an AI workflow after a HOW comment; no transcript. Retain showcase observations, ignore engagement instructions, mark workflow/tool identity unknown and speech missing.
2. Screenshot shows github.com/example-a/orbit-memory. Supplied transcript calls it Orbit Memory, persistent local project notes, 80% less tokens and free forever. Retain purpose while labeling quantified gain and pricing as unverified creator claims.
3. A second reel calls it OM and shows the same exact repository. It explains a short note index first, relevant full notes on demand and stale-note review. Merge with fixture 2, synthesize the mechanism and purpose, identify this explanation as clearer, preserve both sources and caveat.
4. Screenshot says context optimizer with an orange icon. Supplied search candidates are example-a/context-index (100 stars, indexed local notes) and example-b/context-cloud (90,000 stars, hosted cache); neither matches an identifier or branding. Preserve both leads, keep identity unresolved and do not choose by popularity.
5. github.com/example-fork/orbit-memory is expressly described as an incompatible fork. Keep a separate entity, preserve the attributed fork relationship and avoid inheriting the original's capabilities or claims.
6. handy.example/tools/color-contrast is shown performing foreground/background contrast checks, with no transcript. Retain its page and practical use without requiring GitHub or inventing AI functionality. Expose missing speech.

## Baseline

An independent agent without the custom skill handled the core identity, deduplication and evidence distinctions correctly. There was no observed baseline safety failure. The new skill formalizes a reusable library contract, source ledger, synthesis and resume behavior; this evaluation does not claim a measured improvement over baseline.

## Forward test and revision

A separate independent agent read the skill and library contract and applied all six fixtures. Its first review identified a tension between grouping identical repository coordinates and waiting for primary-source verification, plus gaps for evidence-only and no-write pilots. These were corrected in the instructions and contract.

The agent reapplied the fixtures and reported no substantive extraction failure: one merged Orbit Memory record with an explicit synthesized explanation, separate incompatible fork and website records, unresolved optimizer candidates and a showcase observation. All six source records remained separate. Unsupported token/pricing claims stayed attributed and unverified; no audiovisual completeness was asserted.

The final review suggested clearer bookkeeping for evidence-only versus partial status. The release separates review scope from processing state and reports scope counts independently; this wording change received author review rather than another independent full run.

## Limits

This tests reasoning over six synthetic evidence records, not live web search or a full saved-collection run. The earlier real one-reel pilot separately demonstrated link download and visual extraction, with speech missing. No claim is made that 432 reels have been analyzed or that automatic hidden-tool identification always succeeds.

## Version 1.0.1: showcase filtering regression checks

The prior extraction retained researched development tools and a creator-profile lead for a pure website showcase. The user requested link-only output instead. This is the observed behavior motivating this revision.

An independent evaluator applied the updated skill to four synthetic fixtures:

- Pure showcase, verified displayed URL https://showcase.example/, external Three.js/GSAP case study and unrelated profile-builder link: user library retains only the showcased URL; supporting provenance stays private.
- Unidentified showcase plus comment HOW caption: no library entry; skipped-no-supported-extraction in private ledger.
- Substantive tutorial of https://contrast.example/ demonstrating a color contrast checker: retain the URL plus supported purpose and use; do not invent standards, pricing or setup.
- Unnamed tool with two equally plausible candidates and missing speech: no identified-tool entry; private candidates and skipped outcome retained, original-media coverage gap exposed.

All four expected extraction outcomes passed. The evaluator flagged a pre-existing processing-state ambiguity; final wording separates evidence-only completion from missing original-media speech. That narrow clarification received author review. No live services, private export or account data were used in these fixtures.

## Version 1.0.2: researched credits and large-library organization

This supersedes the previous blanket showcase link-only limit. Four independent synthetic cases passed: (A) an exact-project developer portfolio explicitly listing Three.js and GSAP retains those tools as researched credits, with implementation responsibilities unknown and unrelated profile-builder links omitted; (B) a verified showcase without tool credits retains only its link, ignoring stylistic similarity to frameworks; (C) an unidentified showcase is skipped; (D) a second reel for an existing exact repo improves the same entity explanation and page, preserving both sources and conflicting token claims rather than averaging them or duplicating the tool. The existing local index/database/ledger/checkpoint layout is reused and synchronized. Final ledger outcome naming was aligned by author review. No private collection data is part of these fixtures.

## Version 1.0.3: high-confidence identities without creator links

This supersedes the blanket exclusion of inferred identities. Four independent synthetic cases passed: (A) distinctive screenshot labels and an unusual spoken mechanism strongly match one tool's supplied primary documentation, while alternatives contradict a unique feature: include with an explicit high-confidence inferred label, evidence locators and researched official source; (B) generic project-memory language plus a 90,000-star repo: skip unsupported identification; (C) equally matching tools/forks: keep unresolved candidates private and skip; (D) an existing canonical entity gains a new high-confidence inferred reel contribution without changing the older confirmed association or creating a duplicate tool page. The evaluator identified overlap between direct identifiers and feature matching; final wording clarifies that direct explicit identifiers can confirm a match while assembled feature matching remains inferred. This final boundary wording received author review. No live browsing or collection data used in these synthetic checks.
