# Tool Advisor

Coordinate a scoped task using verified capabilities and a durable record. The current assistant is the coordinator; specialist files are instructions, not running agents.

**Before execution, present the specific combination and obtain the user's confirmation.** A broad build request or deadline does not confirm an unseen combination. Reuse an existing confirmation only for the same brief and proposal. This is the user's requested workflow. Small isolated edits and explanation-only questions take the ordinary direct path.

## Start or resume

Locate the research checkout from the managed global instructions. Run the advisor installation check documented in that checkout's README; missing files or inaccessible research stay explicit gaps. Read the project ledger before planning resumed work. The bundled `scripts/ledger.py` is the local state tool; read [the command contract](references/ledger.md) before using it. The coordinator alone writes state. An existing project tracker remains the task source; link its IDs in task evidence.

## Interview

**Required skill: grilling (Matt Pocock).** Invoke the available skill, or read its complete installed SKILL.md and explicitly use its interview instructions. Record whether use was native invocation or manual loading; a name in a plan is not execution. If unavailable, report the missing dependency and prepare setup; do not claim Matt's interview ran.

Host adaptation: the coordinator looks up interview facts. Project worker dispatch starts after combination confirmation. State this adaptation when using grilling, whose original instructions delegate factual research automatically. A host with no worker tools can still conduct the interview.

Use the supplied context to settle known branches. Ask about remaining decisions and look up accessible facts. Capture goal, deliverables, constraints, success criteria, assumptions and open questions in the brief. A complete existing brief needs no repeated questions. Confirm shared understanding together with the proposed combination before execution.

## Discover and propose

**Required skill: find-skills (Vercel).** Load it when entering discovery, then follow [the discovery contract](references/discovery.md). Search each necessary job across the repo, accessible installed capabilities and external sources. Read the full shortlisted instructions and supporting files at checked revisions. Source popularity and creator summaries are leads, not suitability verdicts. Repo review/install rules govern adoption.

Present the task-to-role mapping, sources/revisions, readiness, overlap, costs and gaps. Save the brief, roles and dependency-aware task plan. Show the proposal digest and wait for the user's actual answer. Record that answer with `confirm`; a self-authored approval is invalid. Changes to scope or selected capabilities require a new proposal and confirmation.

## Coordinate and verify

After confirmation, prepare missing selected capabilities under the repo's inspection rules, record readiness evidence, and follow [the execution contract](references/execution.md). Use actual host worker tools when available and authorized; otherwise disclose sequential execution by the coordinator. Start only ready tasks with completed dependencies. Track real actors, blockers and results. Verify acceptance evidence before marking tasks done.

Finish only after all agreed deliverables are verified. Save a sanitized decision in the research repo with source revisions, results, failures and user corrections. Keep raw project state local. Instructions and a ledger support this process; they do not guarantee host obedience or universal discovery.
