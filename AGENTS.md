# Maintain this tool knowledge and Codex setup repository

Read global/AGENTS.md for setup/inspection/sync rules. This repo is also a persistent tool and skill advisor, not only a setup backup. For capability discovery, tool comparisons, skill combinations or setup improvement, read knowledge/ADVISOR.md and follow it. Search knowledge/reel-library/, knowledge/decisions/, github-repos/ and inventory.json; distinguish research from reviewed payloads and current device observations. Read relevant installed skills and verify current upstream revisions before recommending replacements. Preserve original research and append evidence-backed learnings.

For task depth, requirements documents, confirmation reuse, tracking and review coordination, follow knowledge/BUILD-FLOW.md, the authoritative workflow policy. Use its explicit host adaptations with the installed tool-advisor and original selected specialist skills. This file owns repository maintenance rules, not a second copy of the workflow.

"Setup tool-advisor" selects the complete approved baseline in advisor-baseline.json up front. The --install-advisor option requires all baseline roles to be packaged and risk-triaged in advisor-bundle.json; a three-skill partial core is not full setup. --plan-advisor lists preparation gaps; --install-advisor-core is an explicitly requested partial installation only. Use scripts/setup.py to scan/install it and --check-advisor to verify its files, receipts and managed instructions. No arguments remain read-only. Keep all original catalog/inspection rules for other skills. Record test-profile installs as isolated tests, never as the user's laptop installation.

On "setup my Codex using this repo", follow the short flow in README.md: list the catalog first, ask which skills or all eligible skills, then install only the chosen skills after inspection. Plugins/MCPs are a manual setup checklist. Use scripts/setup.py to display the catalog; --install-rules explicitly restores global/AGENTS.md only into Codex's user instructions. No arguments must not modify the device.

Publish verified sanitized setup changes under the user's standing authorization, preserving other devices' work. Do not record unavailable payloads or unchecked installs as ready/successful. Keep explanations short and avoid placeholder documentation. Run python3 -m unittest discover -s tests -v and git diff --check for changes to setup code.
