## Global SkillSpector security gate (before Tool Advisor)

SkillSpector is the global **pre-activation** security gate for installed agent skills, not another project agent and not a historical audit database. Before installing, updating, restoring, copying or activating a selected untrusted skill, use the scanner on the **actual device**. If missing, install or update the official NVIDIA CLI via its verified instructions (`uv tool install git+https://github.com/NVIDIA/skillspector.git`), then check `skillspector --version`. Scanner bootstrap is a separate trusted setup step and must not run code supplied by the untrusted skill.

The controlled advisor installer `scripts/setup.py --install-advisor` must stage all selected skill payloads **outside active skill paths**, run static-only `skillspector scan <stage> --no-llm --format json --fail-on-incomplete --min-coverage 100` for every skill, and parse the JSON from stdout. Do not run skill scripts, package lifecycle hooks or install scripts before the gate. Verify staged files did not change during scanning and verify installed copies afterwards. A scan verdict is not a malware-free guarantee.

For each fresh scan: allow a complete `SAFE` result; show LOW/MEDIUM findings as warnings with context rather than maintaining manual per-skill approval records; **block** HIGH/CRITICAL or `DO_NOT_INSTALL` findings, failed/incomplete coverage, suppressed findings, unknown results or scanner errors. If a warning credibly suggests credential theft, malicious exfiltration, destructive activity or other dangerous behavior, do not activate it solely because a severity heuristic labels it lower. Do not bypass failures to complete a baseline setup. Scanning all 17 selected skills must succeed before the installer changes active files.

**No per-skill audit history or approval ledger is required.** Keep only the versioned Git skill source, the manifest of selected components, and small local installation receipts/snapshots needed to protect files and recover from failed updates. Existing installation histories are setup facts, not scanner approval evidence. Manual skill/plugin installs outside the controlled installer must enforce the same stage-before-activation policy; the scanner cannot enforce it merely by existing on PATH.

Native Claude Code/Codex `PreToolUse` hooks are an **additional best-effort interception layer** for recognized direct skill/plugin installs and active-directory writes. On the actual device, install/check them explicitly with `scripts/setup_security_hooks.py --host claude|codex --install|--check` after reviewing existing settings. Hooks do not intercept every shell, filesystem, remote tool, plugin manager or user-executed command. Never claim universal protection or live host activation without testing. Consult [the security setup guide](https://github.com/bryanhon98/dev-workspace/blob/main/docs/SECURITY-HOOKS.md) for gaps and rollback.

The remaining workflow is unchanged: choose task-specific capabilities through Tool Advisor, use the original Superpowers baseline and Council where selected, preserve official source revisions, avoid unapproved providers/credentials and store no secrets. Low-risk scanning warnings do not replace normal permission and project scope constraints.
