## Scan before installing, updating or restoring skills

Current user policy (2026-11-03) supersedes earlier blanket source-review and block-every-finding requirements for skill installation:

- Check the official source for a newer version at setup/update time. Stage the selected current compatible version outside active skill directories and scan its exact complete payload immediately before installation. Do not automatically reuse an older snapshot merely because it was previously approved. If the newest version is incompatible, explain that rather than silently substituting an older version. This is not background auto-updating.
- No separate manual source-code/security review is required unless I explicitly request it. Reading SKILL.md to understand suitability and to use it correctly remains necessary; it is not a full code audit.
- For a batch, stage and scan every selected skill and its available supporting files before deciding which to activate. Use local static-only SkillSpector; preserve scanner version, file hashes, reports and coverage. Do not execute candidate code merely to scan it or send source to another model service without authorization.
- Triage scanner findings. Document and warn, then proceed without another approval for reasonably established low-risk findings or false positives. Block malware, credential theft, unexplained data exfiltration, serious destructive behavior, safeguard bypasses, or other materially dangerous findings. Scanner severity alone is not the decision; check enough flagged context to explain the classification. This targeted triage is not a routine full source review.
- Resolve missing referenced files and rescan where possible. Failed scans, absent reports, unread executable dependencies or other gaps that prevent risk classification remain blockers. A missing optional/project-generated reference may be documented and warned about when its nonessential role is established. Never suppress findings, fabricate coverage or call an incomplete scan complete just to obtain a pass.
- Install eligible skills, verify installed hashes and host discovery, preserve locally modified copies, and report blocked skills individually. Do not call the complete workflow ready when a required baseline skill is blocked. A scan does not prove a skill or external service harmless; report its actual scope.
- Existing saved audits remain historical evidence. The new warning-and-proceed policy does not retroactively mark untriaged findings accepted. Scanner bootstrap provenance, secrets handling, provider permissions and plugin/account setup rules remain separate.
